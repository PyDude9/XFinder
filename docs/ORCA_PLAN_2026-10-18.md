# Kế hoạch dùng Orca làm IDE multi-agent cho XFinder (2026-10-18)

Nguồn: tài liệu chính thức của Orca (onorca.dev/docs: ways-to-run, model/worktrees, cli/reference, cli/orchestration,
recipes/parallel-agents, agents/hooks-memory) và README trên GitHub (stablyai/orca, MIT). Mọi câu "Orca làm X" dưới đây
là đọc từ tài liệu, **chưa đo trên máy này** — mục 5 là việc phải đo trước khi tin.

## 1. Orca là gì, và nó khớp chỗ nào trong routine hiện có

Orca (Stably AI, MIT) là một "agent development environment": mỗi việc là **một `git worktree` riêng** với terminal, diff
viewer, trình duyệt tích hợp; agent chạy trong đó là CLI của chính bạn (Claude Code, Codex, OpenCode, Cursor CLI, Antigravity
được liệt kê trong README). Có CLI (`orca …`), app di động để duyệt/trả lời từ xa, chạy được qua SSH hoặc `orca serve`.

Routine XFinder hiện tại (docs/AGENT_NOTION.md): **Notion = hàng đợi/trạng thái, Git = đặc tả + code + gate, Claude viết
spec và review, Builder (OpenCode/Zed/Antigravity) làm trên nhánh `agent/<tool>-<ID>`.** Orca thay đúng MỘT lớp: *nơi
Builder chạy*. Thay vì bạn mở kitty, `git switch`, dán prompt — Orca tạo worktree, đặt tên nhánh, mở agent, dán prompt, và
cho bạn nhìn diff khi xong. Notion vẫn là nguồn sự thật về "việc nào, trạng thái gì"; Orca không thay nó (Orca tích hợp
GitHub/Linear/Jira, không có Notion).

| Lớp | Hôm nay | Với Orca |
|:--|:--|:--|
| Hàng đợi, claim, Run, Decision | Notion | **Notion** (giữ nguyên) |
| Đặc tả, gate, rule | Git `docs/specs`, `scripts/gate-all.sh` | Git (giữ nguyên) |
| Chỗ Builder chạy | kitty/Zed, checkout chính, `git switch agent/…` | **Orca worktree**, nhánh = `agent/<tool>-<ID>` |
| Nhiều Builder song song | không (một checkout) | mỗi Builder một worktree, không giẫm nhau |
| Review | Claude đọc `git log main..agent/…` | Claude đọc diff trong Orca **hoặc** như cũ — Orca không bắt buộc |
| Merge vào main | Claude, local (Q-PROC-1) | **giữ nguyên** — không dùng nút "open PR" của Orca (repo private, chính sách merge local) |

## 2. Những điều Orca làm được mà routine đang thiếu

1. **Chạy song song an toàn**: hai Builder trên hai worktree (`T14d` và `XF-T20`) không đụng file nhau; không còn cảnh
   "17 task + 1 feature trong một cây uncommitted" (review DeepSeek 2026-10-15).
2. **"Đua" ba agent cho việc khó** (recipe *parallel agents*): cùng một spec, ba worktree `fix-x`, `fix-x-2`, `fix-x-3`
   với Claude Code / Codex / OpenCode; xem ba diff, chọn cái thắng, xoá hai cái kia bằng một click. Đúng chỗ dùng: bug mà
   hai lần sửa trước không ăn (CLAUDE.md: "after two failed corrections, start fresh").
3. **CLI để Claude điều phối thay vì bạn**: `orca worktree create --name agent/opencode-XF-T20 --agent opencode --prompt
   "<prompt Builder §10>" --setup inherit --json` → `orca terminal wait --terminal <h> --for tui-idle --timeout-ms …` →
   `orca worktree set --workspace-status in-review`. Claude có thể tạo việc cho Builder ngay khi set `Ready` trong Notion.
4. **Trạng thái agent trên UI** (working / waiting / done) qua **hook do Orca cài** vào `~/.claude` và `~/.codex`
   (Settings → Agents → Agent status hooks; `orca agent hooks on|off`). Lưu ý mục 4.3.
5. **Mobile**: duyệt permission / trả lời agent từ điện thoại khi bạn rời máy — đúng lúc Claude hết quota và Builder đang
   hỏi.

## 3. Thiết lập đề xuất cho repo XFinder

1. Cài: `brew install --cask stablyai/orca/orca`. Thêm repo `/Users/wolong/github/XFinder`, base ref `origin/main`.
2. **`.worktreeinclude`** (file ở gốc repo, Orca copy các file bị gitignore vào worktree mới): phải có `CLAUDE.md` —
   nó bị `.gitignore` (dòng 24), nên một worktree sạch sẽ **không có CLAUDE.md** và Claude Code trong đó đọc `AGENTS.md`
   (pointer 1,4 KB) rồi hết. Đây là lý do CLAUDE.md phải gọn (xem phần tái cấu trúc 2026-10-18) — nó được copy vào mọi
   worktree.
3. **Setup hook** (Settings → Repository → Hooks): không cần cài gì (không npm); dùng để **in ra** hai dòng cho agent:
   `export XF_OUT=$TMPDIR/xf-$(basename $PWD)` và nhắc `scripts/gate-all.sh` đọc `XF_ROOT`/`XF_OUT`. Lý do: build-and-check
   mặc định vào `/tmp/xfinder-clean-build` — hai worktree build cùng lúc sẽ ghi đè nhau (rule "one build at a time" trong
   AGENT_TASKS §1 tồn tại vì thế). Với `XF_OUT` riêng, song song được — nhưng mỗi thư mục build mới lại đăng ký
   `com.xfinder.app.XFinderSync` với LaunchServices; sau mỗi worktree bị xoá chạy `lsregister -u <XF_OUT>/XFinder.app`.
4. **Branch name** luôn đặt tay theo `agent/<tool>-<ID>` (ô "Branch name" trong Advanced khi tạo worktree, hoặc `--name`
   trong CLI — kiểm tra xem `--name` thành tên nhánh hay cần cờ riêng: mục 5.2).
5. **Không bật** "Open PR" / "commit & push" từ Orca cho repo này — vi phạm Q-PROC-1 (Builder không push; Claude merge).
6. Mutation harness (`scripts/mutation-check-*.sh`) **sửa source rồi restore**: chỉ chạy trong worktree của chính mình, không
   bao giờ trên checkout chính khi một worktree khác đang build từ cùng cây (worktree là cây riêng nên an toàn; checkout
   chính thì không).

## 4. Rủi ro phải nói trước

1. **Hook chồng hook.** `~/.claude/settings.json` đã có hook của OneNotch, Notch Crew và XFinder (PermissionRequest 3600 s /
   86410 s). Orca cài thêm hook trạng thái của nó. Claude Code chạy mọi hook khớp **song song**, nhưng cách gộp nhiều
   PermissionRequest **không có trong tài liệu** (T-P5-MULTI). Với Codex, Orca "chỉ ghi hook khi có thay đổi" vì mỗi thay
   đổi hook là một lần Codex đòi trust lại (`/hooks`) — và trust của Codex tính theo **vị trí** trong mảng, nên hook của
   Orca chèn trước có thể làm hook XFinder mất trust (P5a đo). Đo mục 5.4 trước khi bật.
2. **Hiệu năng máy**: Orca là app desktop đa nền tảng với trình duyệt nhúng; chưa đo CPU/RAM nhàn trên máy này. XFinder
   có mục tiêu 0 % idle — Orca không phải XFinder, nhưng nếu nó ăn vài % nền thì các phép đo idle của XFinder phải làm khi
   Orca tắt.
3. **Orchestration là Experimental** (Settings → Experimental); lệnh cũ `orca orchestration run` "perform no effects". Dùng
   worktree + terminal CLI trước; orchestration (Run/Task/Dispatch/gate) để giai đoạn 3.
4. **Orca không biết Notion.** Trạng thái phải được Builder tự ghi vào Notion như routine (claim, Run) — Orca chỉ cho thấy
   "agent đang chờ bạn". Không coi badge của Orca là trạng thái việc.
5. **`.worktreeinclude` copy, không symlink**: sửa CLAUDE.md trong một worktree **không** lan sang checkout chính. Chỉ Claude
   sửa CLAUDE.md, trên checkout chính (như hiện nay).

## 6. Lộ trình

- **Giai đoạn 0 (một buổi, bạn làm tay):** cài Orca, thêm repo, `.worktreeinclude`, setup hook in hai dòng `XF_OUT`.
  Đo T-ORCA-1…3, 5.
- **Giai đoạn 1 (pilot = T14d):** Claude set `Ready` trong Notion, tạo worktree qua CLI với prompt Builder §10, Builder
  (OpenCode/DeepSeek) làm trong Orca, Claude review diff trong Orca, merge local như cũ. Đo T-ORCA-6.
- **Giai đoạn 2 (song song):** hai Builder, hai worktree, hai task độc lập (ví dụ T14e và một task XF-T2x) — kiểm "không
  giẫm nhau" và gate song song với `XF_OUT` riêng.
- **Giai đoạn 3 (đua):** việc khó → 3 worktree, 3 agent, cùng spec; Claude so diff, chọn, xoá hai. Chỉ khi Giai đoạn 2 sạch.
- **Giai đoạn 4 (tuỳ chọn):** `orca orchestration` để Claude làm coordinator (run-create → task-create → worker-start →
  `check --wait` → `worker_done`), thay cho việc Claude dán prompt tay. Chỉ khi Experimental đủ ổn.

Câu hỏi cho bạn: **Q-ORCA-1** — bật Agent status hooks của Orca (tiện) hay giữ settings.json như hiện nay (ít rủi ro với
trust của Codex)? Mặc định tôi đề nghị: **giữ nguyên** cho tới khi T-ORCA-4 đo xong.

## 7. Luồng chuẩn 2026-11 (áp từ 2026-11-04)

Vai trò: **Boss** = phiên Claude có `git rev-parse --show-toplevel` là `/Users/wolong/github/XFinder` (hoặc
`XFinder-claude`) — nơi DUY NHẤT viết spec, review, merge, cài. Mọi worktree Orca khác chạy **Builder** theo `BUILDER.md`.
Tối đa **2 Builder** cùng lúc; mỗi worktree 1 agent, 1 task; phiên dài hơn ~40 tin nhắn → kết thúc, mở phiên mới kèm report.

```
1. Boss viết docs/specs/<ID>.md → commit trên main
2. Boss tạo worktree (cú pháp đã đối chiếu `orca worktree create --help`, Orca 2026-11):
   orca worktree create --repo path:/Users/wolong/github/XFinder --name <tool>-<ID> \
     --branch agent/<tool>-<ID> --base-branch main --agent <tool> --setup run \
     --prompt "Đọc BUILDER.md, làm docs/specs/<ID>.md, báo cáo theo mẫu trong BUILDER.md" --json
3. Builder code + `sh scripts/gate-all.sh` + report (KHÔNG cài, KHÔNG push, KHÔNG merge)
4. orca worktree set --worktree branch:agent/<tool>-<ID> --workspace-status in-review
5. Boss: git log main..agent/<tool>-<ID> (rỗng = nói thẳng) → review diff → gate lại trong worktree đó
   (XF_ROOT=<wt> XF_OUT=/tmp/xf-review-<ID> sh <wt>/scripts/gate-all.sh) → merge vào main → Boss cài → chủ dự án test T-*
6. orca worktree rm --worktree branch:agent/<tool>-<ID> --delete-branch
```

**Việc khó** (đã sửa hỏng 2 lần): "đua" — cùng spec, 2–3 worktree `agent/<tool>-<ID>-a|b|c`, mỗi tool một cái. Boss so
bằng bảng: gate xanh? · số file đổi · đụng vùng cấm (`docs/AGENT_TASKS.md` §2)? · test mới có đỏ được không (mutation) ·
đúng spec? → chọn 1, xoá phần còn lại.
